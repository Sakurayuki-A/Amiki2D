## 一、核心算法：解析式覆盖率（Analytic Coverage）

### 1.1 为什么不用传统方法

| 方法 | 代表 | 问题 |
|---|---|---|
| 扫描线 + 采样超采样 | 老 Skia | AA 是估计值；CPU 状态机难并行 |
| 几何细分 + stencil-cover | D2D GPU / Pathfinder | 每帧几何爆炸；内外判定靠 stencil 精度 |
| 距离场 | 文本专用 | 曲线近似，质量有上限 |
| **解析覆盖率（线积分）** | font-rs → piet-gpu → Vello | **逐像素数学精确，无状态，天然并行** ✓ |

### 1.2 数学推导（M1 已实现，CPU 与 WGSL 共享）

设像素 P 的水平区间 `[x_l, x_r]`、行带 `y ∈ [y_c−½, y_c+½]`，路径内部由绕数 `W(x,y)>0`
定义（nonzero）。像素覆盖率：

```
C(P) = ∫∫_P [W>0] dA
```

把覆盖分解为逐扫描线的水平长度，再交换积分次序。对某条扫描线 y，绕数在段穿越点处
跳变。引入"从像素左边缘起算的绕数积分"：

```
G(y) = ∫_{x_l}^{x_r} W(x,y) dx  =  Σ_seg  s · ∫ (clamp(x(y), x_l, x_r) − x_l) dy
```

其中 `s = sign(dy)`（+1 向下穿越、−1 向上穿越，屏幕坐标系），`x(y)` 为线段在该扫描线
上的横坐标。于是每个像素的覆盖率是**各线段贡献的独立和**：

```
C(P) = clamp( Σ_seg  s · ∫_{y∈行带∩段跨度} (clamp(x(y)) − x_l) dy , 0, 1 )
```

三个关键性质：

1. **无状态**：每个像素独立求和，不需要扫描线间的 carry —— 每线程一像素的 GPU 布局
   因此成立；这是整个算法体系 selectable 的根本原因。
2. **精确 AA**：积分对线性段是闭式解（梯形/三角形分片），不是采样估计。边缘像素的
   α 来自真实面积，放大不抖动。
3. **clamp 处理三种情形**：穿越点在像素左侧 → 贡献 0；右侧 → 贡献全宽（绕数 +1）；
   中间 → 梯形面积（部分覆盖）。`clamp(·,0,1)` 同时消化 W>1 的重叠同向区域与反向的
   挖洞区域。

**精确性条件（重要）**：当绕数在单个像素内同时出现 W≥2 与 W=0（例如自相交多边形的
交叠顶点行）时，`clamp(|∫W|)` 会把 W=2 的超额与 W=0 的缺口平均，产生高估
（pentagram 测试中实测 ≤0.2/像素）。W∈{0,1} 的常规情形（绝大多数 UI/游戏内容）
数学精确。彻底修复需要逐像素交叉排序归并（§4.3，M2）——Skia 解析 AA 与 Vello
在同类场景下也有相应近似。

分段闭式积分：x(y) 线性，clamp 引入至多两个拐点（x(y)=x_l、x(y)=x_r 对应的 y），
把行带切成至多 3 段，每段 `∫(a+b·y)dy` 闭式。WGSL 与 Rust 实现同一函数 `seg_coverage`。

### 1.3 压平误差控制

贝塞尔压平采用**误差界自适应二分**：以弦长归一化控制点到弦的垂距作为平坦度判据，
ε = 0.1px（设备空间），最深 24 层。**先变换后压平**，保证 ε 恒以像素度量 ——
缩放再大，视觉误差恒定。这是质量的下限保障；极限质量路线见 §4（二次锥/弧长参数化）。

### 1.4 分箱与稀疏化

16×16 tile。**M2f 稠密网格**：线段按保守 AABB 投入 (tile, draw, row) 网格，逐行精确成员 +
前缀和 carry，输出 CSR；GPU 端每 workgroup 恰好处理一个 tile、每线程一像素（画家序无竞争）。
**M3 稀疏桶表**（现为默认路径）：显存与 `tiles×draws` 成比例的稠密网格被替换为四层稀疏结构——

- **strip**（每条 draw × tile 行）：内容 bbox = tile 列区间 × tile 内局部行区间；
- **tile 行列表**（活跃 strip 按 draw 序）与**逐 tile 桶表**（活跃 tile 列表 + 偏移）：
  fine 逐像素只遍历真正覆盖本 tile 的 draw，不再扫描全 draw 网格；
- **稀疏单元**（strip × 行 × 列）：成员计数（CSR）+ carry + 段端点直存（无全局段池引用）。

一切规模由画面实际内容决定：空画布除 `draws × tile 行` 的条带元数据外零分配。
判定语义与稠密网格**逐式一致**，两条路径渲染结果逐字节相同（M3c 对拍验证）。

## 二、当前能力矩阵（M1–M3）

- 仿射变换（先变换后压平，ε 以像素计）
- 二次/三次贝塞尔、任意多边形；nonzero 填充
- 实心色 + src-over；任意数量绘制按序合成；16 种 W3C 混合模式
- 裁剪合成（覆盖率纹理，≤4 层嵌套取交集）
- 解析 AA（与 64× 超采样 brute-force 对拍误差 < 0.03/像素）
- 全 GPU 分箱：**稀疏桶表**（默认，显存与内容成比例）/ 稠密网格（对拍基准）
- 输出：离屏纹理 → PNG；或窗口表面

## 三、路线图

### M2 —— 全 GPU 化流水线（把 CPU 环节逐个下沉）

- ✅ **M2a GPU 压平（已完成）**：均匀并行压平，段数用闭式可证明界——
  二次 `n = ⌈√(|a|/4ε)⌉`（精确界，a = 二阶差分）；三次 `n = ⌈√(1.3·G/ε)⌉`，
  其中 `G = max(|3p1−2p0−p3|, |3p2−2p3−p0|)`（泰勒展开于 `d(t)=t(1−t)g(t)`，
  g 线性 ⇒ 端点取最大；推导见 `amiki-math` 文档注释）。
  实现：count/points 双 compute pass，每线程无依赖、无原子操作；
  1002 条随机+对抗曲线（环/尖点/超长）CPU 误差界性质测试 +
  GPU 逐曲线对拍测试双验证。当前 M2a 保留段数读回 + CPU 前缀和（简化）。
- ✅ **M2b 分箱重构（已完成，GPU 化的前置）**：改为**逐行精确成员 + 纯前缀和
  carry**——分区按行精确成立恒等式，无需聚合成员与排除测试；线段全局池
  零复制（seg_refs 引用）；carry GPU 化路径 = (行, ⌊x_max/T⌋) 桶计数 + 前缀和。
- ✅ **M2c 编码流 v1（已完成）**：AMK1 tag+data 紧凑二进制格式（编解码 +
  渲染一致性测试），可作缓存/传输/绑定交换格式；GPU 端直接解码在 M3。
- ✅ **M2d 裁剪（已完成）**：clip 路径经 main_coverage pass 渲染为覆盖率
  纹理，绘制时逐像素乘入（≤4 层嵌套展开采样）；CPU 侧以 alpha 图镜像。
  覆盖率 u8 量化（1/255）；Vello 式层树 BFS 为后续深化方向。
- ✅ **M2e 混合模式全集（已完成）**：16 种 W3C 模式（含 HSL 非可分离四模式），
  WGSL 与 Rust 逐式镜像，全模式 GPU/CPU 对拍 ≤2/255。
- ✅ **M2f 全 GPU 分箱管线（已完成）**：
    - CPU 每帧只做：场景 → 控制点/直线提取（`build_gpu_scene`，含 CPU 闭式段数）→ 上传。
      不压平、不分箱；段数不再需要读回（CPU 闭式公式 + indirect dispatch GPU 自派发）。
    - 通用 GPU 前缀和（scan.wgsl 三级：块内 Hillis-Steele / 块和扫描 / 偏移回加），
      随机对拍测试通过。
    - 分箱 pass 图：clear → copy+scan(seg_base) → flatten(段端点直出) → emit(桶计数 +
      carry 定点项) →〖读回 4B item_total〗→ copy+scan(桶前缀) → scatter → carry → fine。
      每帧 2 次 submit、1 次 4B 读回。
    - carry 的 GPU 化：按 (draw, tile-row, row) 桶的 **i32 定点原子加**（×65536，
      WGSL 无 f32 原子），桶沿 x 轴移位 +1（画布左外线段计入前缀、右外排除），
      carry = −含当前桶的定点前缀 —— 与 CPU 逐式对应、数学精确。
    - 稠密 (tile,draw,row) 网格：内存与 tiles×draws 成比例；M3 sparse strips 稀疏化对象。
    - **已验证**：GPU/CPU 对拍——纯直线/矩形场景（多 draw、半透明、旋转、multiply、
      跨 tile）差 ≤2/255；前缀和对拍精确一致。
    - **根因复盘（两层，均已修复）**：
      1. CPU 参考引擎仍用自适应压平而 GPU 用均匀压平 → 统一为 `flatten_uniform`
         （首次补丁因文本不匹配静默失败，教训：结构性补丁必须断言生效）；
      2. **真正的根因**：`counts`（每入口段数）按路径遍历顺序入队，而数据缓冲按
         类型分块（quads|cubics|lines）——纯线段或纯曲线场景两者恰好一致，
         混合场景全部错位（曲线拿到 1 段、直线拿到 27 段）。修复：counts 在
         遍历结束后按数据布局顺序重算。
      - 定位手段：PipelineDump 中间数据转储（seg_ends/counters/bucket_sums/
        carries/seg_refs 逐级比对），保留为公开诊断设施。
      - 回归：donut/16 混合模式/嵌套裁剪/多 draw 矩形 GPU/CPU 对拍全部
        ≤2/255（clip 因覆盖率纹理 u8 量化 ≤3/255）。

### M3 —— sparse strips：显存与内容成比例（核心差异化，已完成）

传统光栅器（含 Skia/D2D）的中间面与画布面积成正比 —— 4K 画布空无一物也烧带宽。
M3 把稠密 (tile, draw, row) 网格替换为与**画面实际内容**成比例的稀疏结构。

- ✅ **M3a 活跃 strip 提取**（`strips.wgsl`）：每条 (draw, tile 行) 归并出内容
  bbox（tile 列区间 + tile 内行区间）。语义与稠密 emit **逐式一致**：
  成员 tile 范围、越界丢弃规则、carry 桶的 `[0, tiles_x]` 钳制与「右外段撑右界」
  效应全部镜像（这正是稀疏化不丢内容的关键）。转置布局 `si = tr·draws + d`
  使每个 tile 行的活跃 strip 连续，一次前缀和即可构建有序列表。
  验证：`strips_match_dense_rects`（轴对齐几何逐格相等）/`..._curves`（覆盖性）。
- ✅ **M3b 稀疏桶表 + 稀疏 fine**（默认路径）：
  strip → tile 行活跃列表（d 序 = 画家序）→ 逐 tile 桶表（活跃 tile 列表 + 偏移，
  顺序写入、无原子、确定序）→ 稀疏单元（成员 CSR + 定点桶 + 段端点直存）。
  fine 逐像素只遍历覆盖本 tile 的 draw；每帧 3 次 submit + 2 次 32B 读回
  （分箱规模 / 成员总数）。dispatch 统一用线性 2D 规避单维 65535 工作组上限。
- ✅ **M3c 验证与基准**：
  - **逐字节一致**：`sparse_matches_dense` 对 6 个场景（矩形/曲线/越界/裁剪/
    16 混合模式/旋转叠加）断言 max_diff == 0。
  - **显存**（RTX 3050, Vulkan）：1080p × 10k 曲线 §4.5 目标场景 —— 稠密网格
    需 **20.93 GB**（单缓冲远超 128MB 绑定上限，根本跑不了）→ 稀疏实占 **34.5 MB**
    （约 **600×**；条带 14986 / 单元 132719 / 桶 222539 / 条目 21661 / 成员 483579）。
  - **GPU 时长**（timestamp query）：720p × 64 曲线 **0.095 ms**（稠密 2.67 ms，
    **28×**）；1080p × 10k 曲线 **2.55 ms**（§4.5 目标 < 2ms，此卡为入门级 RTX）。
  - 回归：`sparse_scales_beyond_dense` 断言「稠密越限规模下稀疏可跑且占用 <1/50」。

**已量化的后续项**：帧路径墙钟仍受每帧缓冲重建 + 3 次 submit/2 次读回的同步延迟
（1080p×10k：GPU 2.55ms vs 帧路径 10.1ms）⇒ **缓冲池化 + 合并同步点**是下一个
性能支点；管线数量增长带来的首次创建约 0.6s ⇒ 加 `PipelineCache`。

### M4 —— 文本、渐变、图像、滤镜

- **文本**：shaping（HarfBuzz/rustybuzz 绑定）→ 字形轮廓直接走解析覆盖率管线
  （任意缩放无 mask 模糊，领先 glyph-atlas 方案）→ 变量字体、subpixel 定位、
  hinting 可选；COLRv1 彩色字体。
- **渐变**：linear/radial/sweep 闭式；mesh gradient（GPU 插值，业界极少有 2D 引擎内建）；
  抖动去色带。
- **图像**：mip 链 + 各向异性采样、九宫格、重复模式。
- **滤镜**：dual-Kawase 模糊（O(1) 于半径）、投影（模糊 + offset 合成）、色彩矩阵、
  SVG filter 子集。

### M5 —— UI 底座能力（服务 UI 框架场景）

- **damage region**：保留模式 Scene 增量提交 + tile 级脏区追踪，只重算脏 tile；
- 合成器：层树缓存、RenderTarget 池、invalidate 精确到 tile；
- 输入延迟优化：渲染与 vsync 对齐的帧管线（借鉴 Graphite 的 recorder 思路）。

### M6 —— CPU 引擎转正（通用性的兜底）

- 把 M1 参考实现升级为 **SIMD 常宽管线**（行带分块 + 多线程 tile 并行），
  目标 Blend2D 级吞吐；无 GPU / 远程桌面 / 单元测试全可用。
- 评估 JIT 化管线（Blend2D 路线）作为可选 feature。

### M7 —— 生态

- C ABI（`amiki-ffi`）→ C#/Java/Kotlin/Swift/Python/Node 绑定（Skija 模式）；
- WASM + WebGPU：浏览器内同一引擎；
- HDR / 广色域：rgba16float 线性渲染目标、ICC/色彩管理、感知一致混合。

## 四、已识别的深化方向（极致化清单）

1. **压平**：曲率自适应 + 二次锥（quadratic cone）分段，逼近理论最优段数；
   cusp 检测避免尖点漏段。
2. **覆盖率**：W<0 与同像素内正负抵消的边角情形 → 引入 Vello 的 winding/area 双通道
   分解（每扫描线先 clamp W 再积分），彻底消除 §1.2 的近似条件。
3. **非零填充的解析化**：同像素多交叉的排序归并（tile 内小排序网络）。
4. **数值稳健性**：退化线段（水平/共线/重复点）的规范化预处理；累积误差用
   有理数化关键点（路线图）。
5. **性能模型**：目标指标 —— 1080p、10k 曲线路径、逐帧 < 2ms（RTX 级 GPU）；
   每个里程碑附带基准（criterion + GPU timestamp query）。
   **M3c 实测**（RTX 3050 / Vulkan，`cargo bench -p amiki-gpu`，报告含逐 pass 时间戳）：
   | 场景 | 稠密网格（M2f） | 稀疏桶表（M3b，默认） |
   |---|---|---|
   | 720p × 64 曲线（GPU） | 2.67 ms | **0.095 ms** |
   | 1080p × 10k 曲线（GPU） | 不可行（需 20.93 GB） | **2.55 ms** |
   | 1080p × 10k 曲线（显存） | 20.93 GB | **34.5 MB** |
   | 帧路径墙钟（1080p × 10k） | — | 10.1 ms（GPU 2.55 ms + 分配/同步） |
   目标判定：入门级 RTX 上 GPU 侧 2.55 ms（顶点内容可继续压）；墙钟的主要缺口在
   每帧缓冲重建与 3 submit/2 读回的同步延迟 —— 已列为下一步（缓冲池化 + 同步合并）。
