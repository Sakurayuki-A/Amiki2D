## 三、性能数据

> 全部为 release、RTX 3050 / Windows、`--release` 基准的真实数字。

### 提取（判据 < 0.8 ms）✅

| 用例 | 耗时 |
|---|---|
| `1080p×10k`（**逐帧复用缓冲**，引擎真实路径） | **586–617 µs** |
| `1080p×10k`（一次性调用 `build_gpu_scene`） | 887–982 µs |
| `1080p×1000` | 60 µs |
| `720p×64` | 4.1 µs |

**从 2.03 ms 降到 0.59 ms（−71%）。**

根因是**每帧重新分配约 7 MB**（大于 128 KB 走 `mmap` + 缺页），
不是 push、不是算术、不是并行。详见 `CHANGELOG.md`。

### 帧路径（判据拆成三项口径）✅

| 口径 | 实测 | 判据 |
|---|---|---|
| 主机侧渲染（提取 + 分配 + 上传 + 编码） | **2.2–2.8 ms** | < 3 ms |
| GPU pass（时间戳） | **2.1 ms** | < 5 ms |
| 保护性同步读回 | 4.3–4.6 ms | 只设上限 |

第三项**不作为性能目标**：它买的是"绝不静默画出残缺帧"（判据第 3 条）。

### 启动开销（判据 < 200 ms）✅

| 配置 | 冷启动 |
|---|---|
| 改前（枚举全部后端） | 337 ms |
| **改后（平台首选 + 全量回退）** | **61 ms** |

### 增量渲染

| 场景 | 平均重画 tile |
|---|---|
| 全屏动画 | 91.5% |
| 静态界面 | 3.5%（**省 96.5%**） |
| **带投影的静态界面** | 3.5%（**省 96.5%**，此前为 0） |

## 五、没有已知的静默错误路径

本项目的一贯取舍：**不支持就显式报错，不静默画错**。本版新增/复查：

| 情形 | 行为 |
|---|---|
| GL 后端遇到位图 | **显式报错**（该后端读不出 `texture_2d_array`） |
| 自建 `wgpu::Device` 上限不足 | `from_device` **先校验再动资源**，返回明确错误 |
| 帧路径遇到含层场景 | 本版已支持；不支持时也是显式拒绝 |
| 投机分配的容量溢出 | 读回实际用量校验，**溢出帧作废重做**（绝不呈现残缺帧） |
| `AMIKI_BACKENDS` 取值非法 | 显式报错并列出可用值 |

## 六、已知限制与未验证项（诚实清单）

### ⚠️ 跨厂商硬件未验证

三个后端全部跑通，但**都在同一块 GPU（RTX 3050）上**。
判据原要求"两个不同厂商的 GPU"，因**单人开发、只有一块显卡**，
已决定**收缩范围**并记为**「已知未验证项」而非「已通过」**。

**这不是走过场**：执行这条验证时抓到过两个"一换后端就起不来"的真 bug
（DX12 的 FXC 循环展开失败、GL 的 `textureSize` 类型不匹配）。
所以未验证意味着**可能还存在厂商/驱动相关的未知问题**。

有第二块显卡时，照 `docs/VERIFY.md` 的清单即可补上。

### 其他已知限制

| 项 | 说明 |
|---|---|
| GL 不支持位图 | 显式报错，不会静默画错 |
| DX12 冷启动约 2.3 s | FXC 运行期编译着色器，非引擎代码问题 |
| 提取的余量不大 | 0.59 vs 判据 0.8（约 26% 余量），但已达标的机制是明确的（消除每帧分配） |
| `cpu_extract` 的一次性调用口径 | `build_gpu_scene()` 仍是 0.89–0.98 ms —— 它是**一次性调用**的成本，逐帧路径不走它 |

### 明确不做（避免范围蔓延）

双向文本（阿拉伯/希伯来）、Knuth-Plass 全局最优断行、HDR / 宽色域、C ABI / WASM。
理由见 `docs/RELEASE_PLAN.md` 第六节。

## 八、本版修复的缺陷（7 项）

1. 层合成两个纹理参数写反 → 层边缘幽灵阴影
2. 模糊 ping-pong 第 2/3 轮读了原图而非上一轮结果 → 只生效一次
3. `inflate_by_filter` 的 DropShadow 原点被平移而非取并集 → 左上被裁（**CPU/GPU 共享**）
4. 排版宽度用 advance_width 相加而非 shaping → 与渲染宽度不符（`AV` 差 7%）
5. `from_device` 不校验设备上限 → 示例启动即 panic
6. WGSL 动态下标导致 DX12 的 FXC 循环展开失败（`X3511`）
7. `textureLoad(..., 0u)` 在 GL 上类型不匹配（`textureSize(sampler2D, uint)`）

### 修复过程中"测试自身不可靠"的三次教训

| 现象 | 原因 |
|---|---|
| `startup_cost` 测出 1598.8 ms（单独复跑 348.4） | 当时刚连跑完 10 轮基准，机器有负载 |
| `profile_frame_path_phases` 主机侧 19.7 ms（单跑 2.35） | `cargo test --workspace` **并行**跑同一二进制，争用 GPU |
| GL 后端主机侧 20.8 ms | GL 走兼容路径，是后端特性不是回归 |

处理：性能断言改为**取多次最小值**，或**只做测量 + 数量级兜底**，
严格判据交给独立基准；三种环境的数字写进测试注释，避免反复调阈值。
