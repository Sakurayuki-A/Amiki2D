# 色彩模型

**这份文档补的是引擎此前完全没定义的一件事**：颜色值到底是什么空间。

## 一句话结论

> **颜色值是 sRGB 编码的，不是线性的。** 引擎把它当作**不透明的数字**做
> 算术（混合、模糊、覆盖率加权），**不在中途做任何色彩空间转换**。
> 唯一的转换点是**输出的色调映射**（可选）。

## 为什么必须写下来

在写 HDR 的过程中，我给色调映射写的第一版测试用了 `4.0` 当"高光源"，结果
两种映射都给出 255，看起来像"没生效"。算了一下才发现：

```
sRGB 编码的 4.0  →  线性 25.3      ← 天文数字的光量
sRGB 编码的 1.5  →  线性 2.57      ← 这才是"高光源"的量级
```

**输入选错了，不是映射坏了。** 而"该用哪个量级"这件事，在没有定义色彩模型时
是**无法判断的** —— 这正是这份文档存在的理由。

## 具体约定

### 1. 取值与含义

| 通道 | 范围 | 含义 |
|---|---|---|
| R/G/B | 常规 `[0,1]`；**允许 >1**（HDR） | **sRGB 编码**的直线色（非预乘） |
| A | `[0,1]` | 覆盖率 / 不透明度 |

- **直线色**：API 收发的都是非预乘值；引擎内部按需转预乘（层合成与模糊用预乘）。
- **sRGB 编码**：`0.5` 表示 sRGB 意义上的中灰，**不是**线性意义上的中灰
  （线性中灰约 `0.214`）。
- **>1 是合法的**：那是 HDR 高光源。`Color` 的字段是公开 `f32`，构造时**不裁剪**。

### 2. 算术发生在哪个空间

**全部发生在 sRGB 编码空间**，与 Skia / Cairo / HTML canvas 一致。

这意味着**混合在色彩科学上是不"正确"的** —— 严格做法应当在线性空间混合。
但这三家都不这么做，而本项目对"与其它 2D 库的行为一致"的重视高于色彩科学上的
严格。**要改成线性混合应当是一次独立的、明确的选择**，不能悄悄改。

### 3. HDR 值在哪里存活

| 阶段 | 精度 | 能否保住 >1.0 |
|---|---|---|
| 图元着色 | f32 | ✅ |
| 层内容（CPU） | f32 | ✅ |
| 层内容 / 模糊 / 输出（GPU） | `Rgba16Float` | ✅ |
| 最终输出到 `Vec<u8>` / 窗口 | 8 位 | ❌ 在那里降下来（**这是设计**） |

主画布在 CPU 侧是 `Vec<u8>` —— 它的最终输出本来就要落到显示范围，
所以不需要全管线改浮点。**层不一样**：层的内容要先经过滤镜，
那一步之前必须保持 HDR。

### 4. 唯一的降范围点：色调映射

[`ToneMap`](../crates/amiki-gpu/src/readback.rs) 决定 >1.0 怎么落到 `[0,1]`：

| 取值 | 数学 | 用途 |
|---|---|---|
| `Raw`（**默认**） | 只 `clamp` | 与其它 2D 库一致；值本来就是显示空间 |
| `Reinhard` | `x / (1 + x)` | 便宜、保序，高光源保留层次 |
| `Aces` | Narkowicz 2015 拟合 | 观感最好，电影/游戏常用 |

**顺序很重要**，因为 `Reinhard` / `ACES` 是**在线性光上定义**的：

```
sRGB 编码值 → 解码到线性 → 施加映射 → 编码回 sRGB → 量化到 8 位
     Raw 跳过解码/编码这两步（值本来就是显示空间）
```

alpha **不参与映射** —— 它是覆盖率，不是光。

**逐通道还是按亮度？** 这里用**逐通道**。严格做法应当在亮度上做映射再按比例
还原颜色（否则会偏色），但逐通道是通行简化（Narkowicz 原文也是这么用的）。
需要严格做法时，那应当是一个独立的、明确的选择。

### 5. 已知的不一致

`ToneMap` 目前通过 GPU 侧的回读 API 使用：

```rust
let px = renderer.readback_f32(&tex)?;              // f32，不裁剪
let out = rgba8_from_f32_with(&px, ToneMap::Aces);  // 降范围
```

**还没有接进 `render_blocking` / C ABI** —— 那两条路径固定用 `Raw`。
这是待办，不是设计（见 `docs/KNOWN_ISSUES.md` 的 B13）。

## 关于 "HDR" 这个词

本项目的 HDR 指的是：

- ✅ **高动态范围的值能穿过层与滤镜存活**（不再在层边界被裁到 1.0）
- ✅ **可选的色调映射**把 HDR 压到显示范围
- ❌ **不是** HDR 显示输出（10 位 / PQ / HLG）—— 没有做
- ❌ **不是** 宽色域（Display P3 / Rec.2020）—— 没有做

引擎的 "HDR" 是**内部管线的高动态范围 + 输出时压回 SDR**，
这是 2D 渲染器里"发光效果"需要的那一半。
